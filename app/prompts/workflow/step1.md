# Step 1: ライフイベント検出

## タスク

以下の通話ログを分析し、顧客のライフイベントを検出してください。

## 入力

**通話ログ:**
```
{call_log}
```

**通話メタデータ:**
- 顧客ID: {customer_id}
- 通話日: {call_date}

## 検出ルール

### 明示的発言（confidence: high）

顧客が直接的にライフイベントに言及している場合。

**例:**
- 「来月引っ越します」→ 引っ越し
- 「結婚することになりました」→ 結婚
- 「子供が生まれました」→ 出産・子育て
- 「転職が決まりました」→ 就職・転職
- 「子供が中学に入学します」→ 進学（子供）
- 「来月定年退職です」→ 退職・定年
- 「息子が一人暮らしを始めます」→ 独立（子供）

### 暗示的発言（confidence: medium / low）

直接的な言及はないが、文脈から推測できる場合。ライフイベント自体を明言していないが、状況の変化を示唆する発言。

**例（medium）:**
- 「そっちだと届かないので、○○の方に届くようにしてほしい」→ 引っ越し
- 「主人の分も一緒に」→ 結婚
- 「育休に入った」「赤ちゃんがいるので」→ 出産・子育て
- 「来月から通勤時間が長くなりそう」「覚えることも多いので」→ 就職・転職
- 「あまり外出しなくなった」「仕事を辞めた」→ 退職・定年
- 「そろそろ別々にした方がいいかな」「自分のことは自分で管理してほしい」→ 独立（子供）

**例（low）:**
- 「受験勉強で使いたい」→ 進学（子供）
- 「最近忙しくて」（具体的な状況変化の言及なし）→ 判定困難

### タイミングの判定

イベントの発生時期を以下から選択：
- `1週間以内`
- `1ヶ月以内`
- `3ヶ月以内`
- `半年以内`
- `時期不明`
- `既に発生`

## 出力形式

以下のJSON形式で出力してください。**JSONのみを出力し、他の説明は含めないでください。**

```json
{{
  "call_id": "通話ID",
  "customer_id": "顧客ID",
  "call_date": "通話日",
  "detected_events": [
    {{
      "event_type": "ライフイベント種別",
      "timing": "発生時期",
      "confidence": "high/medium/low",
      "evidence": "検出根拠となる顧客の発言（引用）"
    }}
  ],
  "no_event_detected": false
}}
```

### 出力例

**ライフイベントが検出された場合:**
```json
{{
  "call_id": "CALL-2025-01-10-12345",
  "customer_id": "C-98765",
  "call_date": "2025-01-10",
  "detected_events": [
    {{
      "event_type": "引っ越し",
      "timing": "1ヶ月以内",
      "confidence": "high",
      "evidence": "来月引っ越すことになったので、インターネットの手続きについて確認したい"
    }}
  ],
  "no_event_detected": false
}}
```

**ライフイベントが検出されなかった場合:**
```json
{{
  "call_id": "CALL-2025-01-10-00016",
  "customer_id": "C-10016",
  "call_date": "2025-01-10",
  "detected_events": [],
  "no_event_detected": true
}}
```

## 注意事項

1. **顧客の発言のみ**を分析対象とする（オペレーターの発言は除外）
2. **複数のイベント**が検出された場合は、すべて `detected_events` に含める
3. **根拠が不明確な場合**は検出しない（過検出より未検出を優先）
4. **evidence**には顧客の実際の発言を引用する
