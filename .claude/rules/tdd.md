# TDD（テスト駆動開発）ルール

このルールは、Pythonコードの実装時に**必ず**適用されます。

## 必須ルール

### 新機能・機能変更時

Pythonコード（`app/`、`lambda/`配下）を新規作成または変更する場合、以下の順序で作業すること：

1. **Red（テストを先に書く）**
   - 実装コードを書く**前に**、テストを先に書く
   - `test-specialist`エージェントを使用するか、自分でテストを書く
   - `make test`でテストが**失敗する**ことを確認

2. **Green（最小限の実装）**
   - テストを通す最小限のコードを実装
   - `make test`でテストが**成功する**ことを確認

3. **Refactor（リファクタリング）**
   - 必要に応じてコードを改善
   - テストが通ることを確認しながら改善

### 禁止事項

- テストなしで実装コードをコミットすることは**禁止**
- テストを後から書くことは**避ける**（やむを得ない場合を除く）
- テストが失敗したままコミットすることは**禁止**

### 例外

以下の場合はTDDを省略可能：
- 設定ファイルの変更（`pyproject.toml`、`Dockerfile`など）
- Terraformコードの変更
- ドキュメントのみの変更
- 既存テストがカバーしている軽微な修正

## 実施フロー

```
┌─────────────────────────────────────────────────────────────┐
│ 1. 要件を確認                                                │
├─────────────────────────────────────────────────────────────┤
│ 2. テストを先に書く（Red）                                    │
│    - test-specialist を使用 or 自分で tests/ に作成           │
│    - make test で失敗を確認                                   │
├─────────────────────────────────────────────────────────────┤
│ 3. 実装する（Green）                                         │
│    - python-developer を使用 or 自分で app/ に作成            │
│    - make test で成功を確認                                   │
├─────────────────────────────────────────────────────────────┤
│ 4. リファクタリング（任意）                                   │
│    - make test で成功を維持                                   │
├─────────────────────────────────────────────────────────────┤
│ 5. カバレッジ確認                                            │
│    - make test-cov でカバレッジを確認                         │
└─────────────────────────────────────────────────────────────┘
```

## コマンド

```bash
# テスト実行
make test

# カバレッジ付きテスト
make test-cov

# 特定のテストファイル
uv run pytest tests/test_xxx.py -v
```
