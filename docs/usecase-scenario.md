# CS通話ログ分析 ユースケースシナリオ

## 概要

本ドキュメントは、通信キャリアのカスタマーサービス（CS）通話ログを分析し、顧客のライフイベントを検出してARPU（Average Revenue Per User）向上につなげるシステムのユースケースシナリオを定義する。

## ビジネス背景

### 対象企業

- **業種**: 総合通信キャリア
- **顧客層**: 個人顧客（B2C）
- **提供サービス**:
  - モバイル通信（スマートフォン、タブレット）
  - 固定回線（光回線、ホームルーター）
  - エネルギー（でんき、ガス）
  - エンターテイメント（動画配信、音楽配信）
  - 端末販売（スマートフォン、タブレット、周辺機器）

### ビジネス課題

1. **顧客ニーズの把握困難**: 顧客の生活状況の変化を適時に把握できていない
2. **提案機会の逸失**: ライフイベント発生時の最適なタイミングでの提案ができていない
3. **解約リスク**: 競合他社への乗り換えを事前に察知できていない

### 目指す姿

CS通話ログから顧客のライフイベントを自動検出し、適切なタイミングで最適なサービス提案を行うことで、ARPU向上と顧客満足度の改善を実現する。

## 入力データ仕様

### 通話ログ形式

```json
{
  "call_id": "CALL-2025-01-10-12345",
  "customer_id": "C-98765",
  "call_date": "2025-01-10",
  "call_time": "14:30:00",
  "duration_seconds": 420,
  "call_reason": "契約内容の確認",
  "transcript": [
    {"speaker": "operator", "text": "お電話ありがとうございます。本日はどのようなご用件でしょうか。"},
    {"speaker": "customer", "text": "来月引っ越すことになったので、インターネットの手続きについて確認したいのですが。"},
    {"speaker": "operator", "text": "ご引越しですね。新しいご住所はお決まりでしょうか。"},
    {"speaker": "customer", "text": "はい、東京都渋谷区の新しいマンションに移ります。"}
  ]
}
```

### データ項目

| 項目 | 型 | 説明 |
|------|-----|------|
| `call_id` | string | 通話の一意識別子 |
| `customer_id` | string | 顧客ID |
| `call_date` | string | 通話日（YYYY-MM-DD形式） |
| `call_time` | string | 通話開始時刻（HH:MM:SS形式） |
| `duration_seconds` | integer | 通話時間（秒） |
| `call_reason` | string | 問い合わせ理由（オペレーター入力） |
| `transcript` | array | 会話内容（話者分離済み） |

### 話者識別

- `operator`: カスタマーサービスオペレーター
- `customer`: 顧客

## 検出対象ライフイベント

### 7つのライフイベント

| # | イベント | 説明 | ARPU向上機会 |
|---|----------|------|-------------|
| 1 | **引っ越し** | 住居の移転 | 光回線新規契約、でんき・ガスセット割 |
| 2 | **結婚** | 婚姻、同棲開始 | 家族割、回線追加、端末追加 |
| 3 | **出産・子育て** | 出産、育児開始 | 見守りサービス、タブレット、キッズスマホ |
| 4 | **就職・転職** | 新規就職、転職 | プラン見直し、モバイルWi-Fi、ビジネス端末 |
| 5 | **進学（子供）** | 子供の入学、進学 | 学割、子供用スマホ、タブレット |
| 6 | **退職・定年** | 退職、定年退職 | シニア割、使用量見直し、らくらくスマホ |
| 7 | **独立（子供）** | 子供の一人暮らし開始 | 家族割解除、別契約への移行、新規回線 |

### 検出方針

#### 明示的発言

顧客が直接的にライフイベントに言及するケース。

**例**:
- 「来月結婚するんです」
- 「子供が生まれました」
- 「4月から新しい会社で働きます」

#### 暗示的発言

直接的な言及はないが、文脈からライフイベントを推測できるケース。

**例**:
- 「新しい住所に届けてほしい」→ 引っ越し
- 「主人の分も一緒に契約したい」→ 結婚
- 「最近あまり外出しなくなって」→ 退職・定年

### 確度判定

| 確度 | 条件 | 例 |
|------|------|-----|
| `high` | 明示的な発言あり | 「来月引っ越します」 |
| `medium` | 強い示唆あり | 「新居のことで相談が」 |
| `low` | 弱い示唆のみ | 「住所変更するかも」 |

## 出力仕様

### Step 1: ライフイベント検出結果

```json
{
  "call_id": "CALL-2025-01-10-12345",
  "customer_id": "C-98765",
  "call_date": "2025-01-10",
  "detected_events": [
    {
      "event_type": "引っ越し",
      "timing": "1ヶ月以内",
      "confidence": "high",
      "evidence": "来月引っ越すことになったので、インターネットの手続きについて確認したい"
    }
  ],
  "no_event_detected": false
}
```

### Step 2: 履歴照合・パターン分析結果

```json
{
  "customer_id": "C-98765",
  "current_event": {
    "event_type": "引っ越し",
    "confidence": "high"
  },
  "historical_context": {
    "previous_events": [
      {"date": "2024-06-15", "event_type": "結婚", "confidence": "high"}
    ],
    "pattern_analysis": "結婚後約7ヶ月での引っ越し。新婚による新居への移転と推測される。"
  },
  "is_new_event": true,
  "related_to_previous": true
}
```

### Step 3: レコメンド生成結果

```json
{
  "customer_id": "C-98765",
  "call_date": "2025-01-10",
  "recommendations": [
    {"action": "光回線セット提案", "priority": "high", "reason": "新居への引っ越しに伴う新規契約機会"},
    {"action": "でんき・ガスセット割", "priority": "medium", "reason": "引っ越し先でのインフラ一括契約"},
    {"action": "家族割継続確認", "priority": "low", "reason": "結婚済み顧客のため家族割の適用状況確認"}
  ],
  "life_stage_summary": "新婚期・新生活開始"
}
```

## 処理フロー

```
┌─────────────────┐
│  CS通話ログ     │
│  (S3アップロード) │
└────────┬────────┘
         │
         ▼
┌─────────────────────────────────────────┐
│ Step 1: ライフイベント検出              │
│ - 7つのライフイベントをスキャン         │
│ - 明示的/暗示的発言を検出               │
│ - 確度判定（high/medium/low）           │
└────────┬────────────────────────────────┘
         │
         ▼
┌─────────────────────────────────────────┐
│ Step 2: 履歴照合・パターン分析          │
│ - 過去の検出イベントを取得（SEMANTIC）  │
│ - 新規 or 既知イベントの続報か判定      │
│ - ライフステージの変遷を分析            │
└────────┬────────────────────────────────┘
         │
         ▼
┌─────────────────────────────────────────┐
│ Step 3: レコメンド生成                  │
│ - 検出イベントに基づくアクション生成    │
│ - 優先度付け（high/medium/low）         │
│ - USER_PREFERENCEとして蓄積             │
└────────┬────────────────────────────────┘
         │
         ▼
┌─────────────────┐
│ 顧客別          │
│ レコメンドレコード │
└─────────────────┘
```

## 活用シナリオ

### シナリオ1: 日次バッチ処理

1. 前日のCS通話ログをS3にアップロード
2. 本システムが自動的に全ログを分析
3. ライフイベント検出顧客のリストを生成
4. 営業チームが優先度順にアウトバウンドコール

### シナリオ2: 顧客プロファイル蓄積

1. 顧客Aが「結婚」に関する通話
2. 6ヶ月後、同じ顧客Aが「引っ越し」に関する通話
3. システムが「結婚→引っ越し」のパターンを検出
4. 「新婚期の新居移転」としてライフステージを更新

### シナリオ3: リアルタイムアラート（将来構想）

1. 通話終了直後にリアルタイム分析
2. 重要ライフイベント検出時にアラート発報
3. スーパーバイザーが即座にフォローアップ判断

## 評価指標

### 検出精度

| 指標 | 目標値 |
|------|--------|
| 適合率（Precision） | 80%以上 |
| 再現率（Recall） | 70%以上 |
| F1スコア | 75%以上 |

### ビジネス成果

| 指標 | 測定方法 |
|------|----------|
| ARPU向上率 | 検出顧客 vs 非検出顧客の比較 |
| 成約率 | レコメンド提案からの成約数/提案数 |
| 顧客満足度 | NPS、CSAT |

## 制約事項

1. **プライバシー配慮**: 通話内容は機密情報として取り扱い、分析結果のみを活用
2. **処理時間**: バッチ処理前提（リアルタイム性は不要）
3. **対象外**: 法人顧客、代理店経由の問い合わせ
